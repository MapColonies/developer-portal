# AGENTS.md

## Repo Shape

- This is a single-package Docusaurus docs site, not a monorepo.
- Main config is `docusaurus.config.ts`; docs live under `docs/`, blog posts under `blog/`, static assets under `static/`.
- Global React app wrapping is in `src/theme/Root.js`; use this for site-wide providers/widgets.
- Sidebar structure is mixed: most docs sidebars are autogenerated in `sidebars.js`, but `gettingStartedSidebar` is manually curated.

## Commands

- Install with `npm ci` when matching CI/lockfile behavior; `npm install` is used by README and Docker development image.
- Local dev: `npm start`.
- Production build: `npm run build`.
- Typecheck: `npm run typecheck`.
- Full local Ask AI stack, including Docusaurus: `docker compose -f docker-compose.ask-ai.yml up`.
- The compose stack includes a one-shot `ask-ai-index` service that publishes `ask-ai/data/docs-index-current.json` after writing a completed version under `ask-ai/data/indexes/`.
- `ask-ai-index` caches embeddings by chunk content hash and skips work when docs are unchanged; use `FORCE_REINDEX=true` to rebuild all embeddings.
- Search UI from `docusaurus-lunr-search` is only visible after a production build; README suggests `npm run build && npm start`.
- There are no configured lint, formatter, or test scripts in `package.json`.

## Build And Deploy

- GitHub Pages deploy runs on `master` and builds with Node 18 using `npm ci && npm run build`.
- PR previews build only for changes under `docs/**`, `src/**`, `static/**`, `blog/**`, `docusaurus.config.ts`, or `sidebars.js`.
- `BASE_URL` matters for GitHub Pages: deploy workflow uses `/developer-portal/`, preview workflow uses `/developer-portal/pr-preview/pr-<number>`.
- Docker production build uses placeholder URLs, then `entry-point.sh` rewrites built static files at container startup from env vars.
- Docker serves built files with unprivileged nginx on port `8080` using `default.conf`.

## Environment Fields

- Runtime/build env vars currently wired into Docusaurus config: `PLAYGROUND_URL`, `PUZZLE_URL`, `CATALOG_APPLICATION_URL`, `YAHALOM_APPLICATION_URL`, `BASE_URL`.
- Helm configmap exposes the app URL env vars, but `BASE_URL` is only used during Docusaurus build.
- `src/customFields.ts` is not fully aligned with `docusaurus.config.ts`; check both before relying on custom field typing.

## Docs And OpenAPI

- Redocusaurus specs are configured in `docusaurus.config.ts` and served under docs routes.
- OpenAPI source files are under `static/openapi/**`; update both the YAML and `redocusaurus` route config when adding/removing API docs.
- Docusaurus doc URLs may differ from filenames when frontmatter IDs are used; check existing docs before deriving links mechanically.

## Ask AI Work

- Do not expose real LiteLLM tokens in Docusaurus/browser env vars.
- Preferred Ask AI shape: browser widget -> internal proxy/API -> RAG/index -> LiteLLM.
- For local testing, use Nginx/proxy to inject LiteLLM auth instead of sending auth from the browser.
- User accepted `qwen2.5:0.5b` as the local Ollama chat model.
- Local embeddings use `nomic-embed-text` through Ollama/LiteLLM.
- User prefers avoiding an external vector DB; use the generated local index at `ask-ai/data/docs-index-current.json` loaded in memory before adding Qdrant/Postgres/etc.
- Ask AI backend code lives under `ask-ai/` and intentionally uses built-in Node APIs only.
- Ask AI answers expand top vector hits by reading matched source docs from disk and sending surrounding sections to the model; keep this grounding behavior when changing retrieval.
- Ask AI supports streaming with `POST /api/ask-ai` and `{ "stream": true }`; the frontend consumes `text/event-stream` over `fetch()`.
